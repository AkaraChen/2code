# Optimization & Improvement Plans

Output of a full-codebase analysis of 2code (React 19 frontend, Rust/Tauri 2 backend), run as a multi-agent workflow:

1. **Analyze** — 9 parallel analyzers deep-read every file in their subsystem (terminal, projects/nav, git/settings, shared state, PTY backend, DB/git backend, service/handler, IPC boundary, build/deps/startup).
2. **Dedupe** — 47 raw findings merged into 33 distinct root causes.
3. **Verify** — every performance claim was re-derived from the real code and, where measurable in a container, **benchmarked against the actual implementation** (module-level, realistic input sizes, A/B against a prototyped fix where possible). Findings whose measured win was small or whose cost model didn't survive scrutiny were **rejected**, not planned.
4. **Plan** — each confirmed finding became one self-contained implementation plan below (problem, verbatim benchmark numbers, step-by-step change, verification commands, risks).

**Result: 28 confirmed & planned, 5 rejected after measurement.** Plans are independent unless noted in their Risks sections; file numbers are stable IDs, not priority order — use the severity column.

## Benchmark environment

Linux container, no display (module-level benchmarks only). Rust: `cargo test -p model -p repo -p service -p infra` (151 tests green); the full Tauri app does not build in-container (GTK missing). Frontend: vitest + jsdom, 671 tests green. jsdom/dev-React numbers are inflated vs the production WebView; each plan states what was measured vs extrapolated. Every benchmark harness was deleted after measurement — no benchmark code ships in this branch.
