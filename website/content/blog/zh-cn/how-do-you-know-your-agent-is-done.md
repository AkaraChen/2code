## 你在刷哪个 pane？

四个终端窗口，四个 agent。

第一个在重构 API，跑了六分钟没动静。第二个在修测试，输出停在半屏，看不出是跑完了还是在等你按 y。第三个你早上起的，现在完全想不起来它在干什么。第四个刚起，肯定还早。

于是你开始刷。切一圈，回到自己的编辑器，写了两行，又忍不住切一圈。

你手上并行的是 agent，但你自己是**单线程**的——而且你把这条唯一的线程，用来做了一件计算机最擅长的事：**轮询**。

## 轮询的成本，比你以为的高

每一次「切过去看一眼」都不是一次 tab 切换那么便宜，它是三件事：

1. **决定去看**——这个念头本身就打断了你正在做的事；
2. **重建上下文**——这个窗口刚才跑到哪了？这段输出是新的还是我上次看过的？
3. **判断**——它是跑完了、卡住了、还是在等我确认？

第三步最要命，因为**它经常没有答案**。终端里只有字符，没有状态。一个停下来的 agent 和一个正在思考的 agent，在屏幕上长得可以一模一样。

更糟的是这个循环有自我强化：你越不确定，就越想去看；越频繁地去看，你自己那件事推进得越慢；推进得越慢，你就越觉得「反正也没在专心，不如再刷一圈」。

结果是并行的收益被吃掉了。你起四个 agent 的初衷，是**让它们干活的时候你去干别的**。可你没有去干别的，你在盯盘。

一句话：**没有通知，并行就只是把等待复制了 N 份。**

## 通知不是开关，是一把梯子

这里有个容易走错的方向：一发现「用户不知道 agent 好了」，就把所有事件都做成弹窗，再配个音效。

试两天你就会去设置里把它关掉。因为不是所有事件都值得打断你。

按打扰程度，通知其实是一把梯子，从轻到重大致五级：

| 级别 | 形态 | 打扰成本 | 适合什么事件 |
| --- | --- | --- | --- |
| 0 | 终端标题栏 | 几乎为零，但要你去看 | 原始状态 |
| 1 | 状态圆点（列表里的一个点） | 零打扰，扫一眼就有 | 「跑完了」 |
| 2 | 声音 | 低，但会穿透注意力 | 「需要你拍板」 |
| 3 | 系统通知 | 中，会盖住别的窗口 | 「你人不在，但需要你」 |
| 4 | 手机推送 | 高，跨设备 | 「你不在电脑前」 |

关键不在于做到第几级，而在于**把事件分到正确的那一级**。

同一件事错配一级，体验就会崩：

- 把「跑完了」做成声音 → 四个 agent 一起收工，你的电脑变成老虎机。
- 把「等你确认」做成一个安静的圆点 → 那个 agent 会在权限提示上挂十分钟，白等。

所以真正的问题不是「要不要通知」，而是：**agent 停下来的原因是什么？**

## 两种「停下来」，值得两种待遇

Agent 停下来，只有两种情况，但它们对你的意义完全不同：

**一、它干完了。** 结果已经在那儿了，diff 也在那儿了。你晚三分钟去看，什么都不会损失。这是一条**信息**，不是一次中断。

**二、它在等你。** 权限提示、方案二选一、一个需要你回答的问题。**这时候它一秒钟都没在干活。** 你晚十分钟发现，就是白白浪费十分钟——而如果你同时跑着四条线，这种空转是叠加的。

第一种应该**留在原地等你**，第二种应该**主动来找你**。

分不清这两者的工具，只能在「太吵」和「没用」之间二选一。

## 2code 现在做到哪一层

2code 是一个完整的终端模拟器——你的 shell、prompt、别名、CLI agent 全部照常工作。它在上面加的是一层状态识别，然后把上面那把梯子接了起来。

**识别：从字符里读出状态。** 2code 从三个地方判断 agent 的状态：终端屏幕文本、OSC 标题序列、OSC 进度序列。很多 agent CLI 其实一直在广播自己的状态，只是普通终端不听——比如 Claude Code 工作时会把标题设成一个盲文点阵的 spinner 字符，闲下来会换成 `✳`；它弹权限确认时，屏幕底部会出现「Do you want to proceed?」加上一组编号选项。这些都是可以被识别的信号。

规则按 agent 一份清单地写在仓库里，目前覆盖 18 个：Claude Code、Codex、Gemini、Cursor、Copilot、OpenCode、Amp、Cline、Devin、Droid、Grok、Kilo、Kimi、Kiro、Hermes、Pi、Qoder CLI、Agy。识别结果收敛成两个对你有意义的状态：**running（在跑）** 和 **waiting（在等你）**。

**第 1 级——圆点。** 每个终端标签、侧边栏里的每个工位、每个项目条目上都有一个点：

- 在跑：绿点在轻轻呼吸；
- 在等你：**黄点**；
- 跑完了：一个**静止的绿点**，一直亮着，直到你点进那个标签它才消失。

侧边栏会把一个工位下所有标签的状态汇总成一个点，且「在等你」优先于「在跑」——所以侧边栏那一列点，就是你那几条并行任务线的全景。**跑完了不响，因为它不急。**

**第 2 级——声音。** Agent 从「在跑」翻到「在等你」的那一刻，响一声。音色在设置里挑系统内置的（macOS 走 `/System/Library/Sounds`，Windows 走 `C:\Windows\Media`，Linux 走 XDG 的声音目录），可以试听。**只有「等你拍板」会响，「跑完了」不会。**

**第 3 级——系统通知。** 同样是「在等你」这个瞬间，但多一个条件：**只有 2code 窗口不在前台时才发**。你正盯着这个窗口看，屏幕右上角再弹一条「agent 在等你输入」，那是噪音不是通知。通知的标题带上是哪个 agent，正文是那个标签的名字，你不用点开就知道该回哪一条线。

整套东西**默认是关的**。第一次在设置里打开时会向系统申请通知权限，没授权就只有圆点和声音。我们的判断是：会响的东西必须由你亲自打开一次。

**第 4 级——手机。** 没有。往下说。

## 边界：这不是编排 inbox，也不是手机端

说清楚比说满更重要。

**和 tmux 的区别。** tmux 能让会话活着，也能在状态栏显示窗口有活动——但那是「有输出」，不是「agent 在等你」。一个刷进度条的构建和一个卡在权限提示上的 agent，在 tmux 眼里都是「活动」。2code 判断的是语义状态，而不是有没有字符流过。

**和 Orca 的区别。** Orca 有 mobile companion，人离开电脑也能看 agent 状态。这是上面那把梯子的第 4 级，2code 现在没有，短期也不打算做——它需要一条服务端通道，而 2code 目前完全跑在你自己机器上。所以现在的定位很明确：**它照顾的是「你人在电脑前，但注意力在别处」，不是「你在地铁上」。**

**和 Superset 的区别。** Superset 在解的是几十个 agent 的编排和 review 关卡——一个 inbox，一个队列。2code 不做队列，它做的是**你桌面上这三四条线，有事的时候能找到你**。

**和 Slack bot 的区别。** 往 Slack 发一条「任务完成」，代价是你得离开工作台去看消息，然后再回来。而结果本来就在 2code 里，你要做的是扫 diff，不是读通知。所以我们没往外发，我们让点亮在原地。

这是最小可用闭环，不是完整方案。但它删掉的是那个每天发生几十次的动作：**切过去看一眼**。
